# Netlify Free deployment
Connect only hotdataofficial/hotdata, branch main. Build: node scripts/prepare-netlify.mjs && npm run db:generate && npm run build; publish .next; functions netlify/functions; Node 22. The Prisma Linux target is included for Lambda. No database schema migration is introduced.

## Production variables
Move DATABASE_URL (pooled Neon), REDIS_URL (TLS), APP_URL, CORS_ALLOWED_ORIGINS, JWT_ACCESS_SECRET, JWT_REFRESH_SECRET, AUTH_CODE_SECRET, IP_HASH_SECRET, PROVIDER_ENCRYPTION_KEY and gateway/provider/email settings privately from their owners. Preserve existing signing and encryption keys for existing users/provider rows. Never paste values into chat or source control.
Set APP_URL and CORS_ALLOWED_ORIGINS to the exact new HTTPS site origin. Use Functions and Builds scopes where needed. Set PROOF_STORAGE_DISABLED=true, HOTDATA_WORKER_MODE=netlify, and HOTDATA_WORKER_SECRET to a freshly generated 32-byte lowercase hex value. Keep secret variables restricted to Production. Never attach the production database or service credentials to untrusted previews. A generated build-context guard also disables job execution in preview and local builds. Netlify does not expose CONTEXT to functions at runtime, so it is checked during the build instead.
Keep KORAPAY_ALLOW_LIVE=false and GSUBZ_ALLOW_LIVE=false during migration. Configure PAYMENT_GATEWAY=korapay. Resend needs a verified sender before email recovery works.

## Delivery
After the wallet debit and durable purchase outbox commit, the server awaits an authenticated POST to the background function (only the 202 acknowledgement, not delivery). Both single and bulk purchases trigger it. A failed wake-up leaves the committed outbox intact. Five-minute scheduled recovery checks for due work and wakes the background function; hourly runs handle balance checks and retention. Scheduled functions themselves never call the slow provider.
A database lease prevents overlapping runners. Existing transaction locks, stable provider references, status reconciliation, and idempotent refunds are retained. At most 40 new and 20 pending orders per invocation, with an eight-minute work budget. Crashes leave leases that expire; recovery resumes. Pending/unknown orders are never blindly resubmitted or refunded for a timeout. Notifications use bounded batches and their existing retry outboxes.
The worker endpoint always acknowledges asynchronously on Netlify, including unauthorized requests; authorization is checked before importing database jobs. An HTTP 202 alone does not prove completion: inspect database status and function logs.

## Launch checks
Confirm Netlify bundles both functions and the Linux Prisma engine. With live flags off, verify health/readiness, register/login/PIN, production origin cookies and CSRF, and catalog. Exercise worker authorization, duplicate wake-ups, crash recovery and sandbox order outcomes before activating a provider. Review wallet ledger/test balances and owner administration. Update Korapay webhook/callback URLs to the new site, run a user-approved funding and smallest-bundle test, then enable live flags and the reviewed provider mapping. Do not publish availability until the worker and funding path are verified.
Free includes 300 monthly credits and a hard usage limit: exhaustion can pause service. Monitor usage, do not enable a paid plan or auto recharge. No always-on Render worker is required.
